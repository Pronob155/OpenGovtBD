# Contributing to OpenGovtBD

First of all, thank you for considering contributing to **OpenGovtBD**! ❤️

Our goal is to build an open-source platform that improves communication between citizens and government services in Bangladesh. Every contribution—whether it's code, documentation, UI improvements, bug reports, or feature suggestions—is highly appreciated.

---

## 📌 Ways to Contribute

You can contribute by:

- 🐛 Reporting bugs
- ✨ Suggesting new features
- 💻 Writing code
- 🎨 Improving the UI/UX
- 📖 Improving documentation
- 🧪 Writing or improving tests
- 🌐 Translating content
- 🔒 Improving security

---

## 🚀 Getting Started

### 1. Fork the Repository

Click the **Fork** button on GitHub.

### 2. Clone Your Fork

```bash
git clone https://github.com/YOUR_USERNAME/OpenGovtBD.git
cd OpenGovtBD
```

### 3. Create a New Branch

```bash
git checkout -b feature/your-feature-name
```

Examples:

```
feature/user-dashboard
feature/report-system
bugfix/login-error
docs/update-readme
```

---

## 💻 Development Guidelines

- Write clean and readable code.
- Follow the existing project structure.
- Keep commits small and focused.
- Use meaningful variable and function names.
- Add comments only when necessary.
- Test your changes before submitting.

---

## 🎨 UI/UX Guidelines

When working on the frontend:

- Keep the interface modern and responsive.
- Maintain consistent spacing and colors.
- Ensure accessibility.
- Optimize for desktop and mobile devices.
- Follow the existing design system.

---

## 📝 Commit Message Convention

Please use descriptive commit messages.

Examples:

```text
feat: add citizen complaint dashboard

fix: resolve login validation issue

docs: update installation guide

style: improve navbar responsiveness

refactor: optimize API request handling
```

---

## 🔍 Before Opening a Pull Request

Please make sure that:

- [ ] Code builds successfully.
- [ ] No unnecessary files are included.
- [ ] Existing functionality is not broken.
- [ ] Documentation has been updated if needed.
- [ ] Commit history is clean.

---

## 📥 Pull Request Process

1. Fork the repository.
2. Create a new branch.
3. Make your changes.
4. Commit your changes.
5. Push your branch.

```bash
git push origin feature/your-feature-name
```

6. Open a Pull Request.
7. Clearly describe:
   - What changed
   - Why it was changed
   - Screenshots (if UI related)

---

## 🐞 Reporting Bugs

Please include:

- Operating System
- Browser (if applicable)
- Steps to reproduce
- Expected behavior
- Actual behavior
- Screenshots (optional)

---

## 💡 Feature Requests

Include:

- Problem you're trying to solve
- Proposed solution
- Possible alternatives
- Mockups (optional)
