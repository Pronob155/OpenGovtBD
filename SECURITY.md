# 🛡️ Supported Versions

The following versions currently receive security updates.

|         Version        |      Status     |
| :--------------------: | :-------------: |
|   **Latest Release**   |   ✅ Supported   |
| **Development Branch** |   ✅ Supported   |
|   **Older Releases**   | ❌ Not Supported |
|  **Archived Versions** | ❌ Not Supported |

> **Recommendation:** Always use the latest stable release to receive security updates and bug fixes.

---

# 🚨 Reporting a Security Vulnerability

If you discover a security vulnerability, **please do not disclose it publicly** before giving the maintainers time to investigate and resolve the issue.

Instead, report it privately with as much detail as possible.

Please include:

* 📝 Description of the vulnerability
* 🔁 Steps to reproduce
* 💥 Potential impact
* 💡 Suggested mitigation (if available)
* 📷 Screenshots, logs, or proof of concept (optional)

---

# 📬 How to Report

Open a **private security report** through GitHub's Security Advisories (if enabled), or contact the project maintainers through the repository's official communication channels.

Please avoid creating a public GitHub Issue for security-related vulnerabilities.

---

# ⏱️ Response Timeline

Our goal is to respond promptly.

| Stage                   | Expected Time                  |
| ----------------------- | ------------------------------ |
| Initial acknowledgement | Within **72 hours**            |
| Investigation           | Within **7 days**              |
| Status updates          | As needed                      |
| Security fix            | As soon as reasonably possible |

Response times may vary depending on the severity and complexity of the issue.

---

# 🔍 What Happens Next?

Once a report is received:

1. ✅ We acknowledge receipt.
2. 🔍 We investigate the reported issue.
3. 📊 We assess its impact and severity.
4. 🛠️ We develop and test a fix.
5. 🚀 We release the security update.
6. 🙏 We may publicly acknowledge the reporter (with permission).

If the report is determined **not** to be a security vulnerability, we will explain our reasoning whenever possible.

---

# 🤝 Responsible Disclosure

We kindly ask security researchers to:

* ❤️ Act in good faith.
* 🚫 Avoid disrupting production services.
* 🔒 Keep vulnerability details private until a fix is available.
* 📢 Coordinate disclosure with the maintainers.

Responsible disclosure helps protect all users of the project.

---

# 🏆 Recognition

We sincerely appreciate responsible security reports.

With the reporter's permission, we may acknowledge their contribution in release notes or project documentation after the issue has been resolved.
